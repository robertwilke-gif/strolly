01 Setup im Repo (5 Minuten)

Damit Claude Code dein Strolly‑Universum kennt, lege drei Dateien an. Mehr braucht es nicht.

Dateien ins Repo legen. Im Root deines Projekts: 
/dein-repo/
├── CLAUDE.md      # Was Claude Code beachten soll (Workflow, Konventionen)
├── BRAND.md       # Design Tokens, Voice, Komponenten
└── assets/
    ├── strolly-logo.svg
    ├── strolly-mark.svg
    └── strolly-wordmark.svg
Claude Code starten im Projekt‑Root: 
claude
Beim ersten Start liest Claude automatisch CLAUDE.md – es muss nicht im Prompt erwähnt werden.
Verifizieren, dass es geladen ist. Frag im Chat:
Welche Brand-Tokens stehen in BRAND.md für Primary und Navy?
Wenn er #00B3B3 und #0D1B2A nennt → alles gut.
Optional: .cursorrules für Cursor-User mit derselben Quintessenz – aber wenn du wirklich Claude Code nutzt, reicht CLAUDE.md.
Tipp: Lege BRAND.md nicht in einen Unterordner. Im Root bleibt es für alle Tools auffindbar (Claude Code, IDE‑Suche, GitHub‑Preview).

02 Die 5 Prompting‑Prinzipien

Diese fünf Punkte machen 90 % des Unterschieds zwischen „funktioniert irgendwie" und „liefert wie ein Senior Dev".

① Kontext zuerst, Aufgabe danach

Sag Claude erst, wo er hinschauen soll, bevor du sagst, was zu tun ist.

GUTLies BRAND.md (Voice + Tokens) und components/ui/Card.tsx. Baue dann eine Section <UpcomingCities /> für die Landing.
SCHLECHTBau mir eine Section für kommende Städte.

② Constraints explizit machen

Was darf er nicht? Welche Lib? Welcher Style? Sei kleinlich – Claude liebt klare Grenzen.

GUTConstraints: - Keine neuen Dependencies - Icons nur aus lucide-react - Komponente unter components/sections/UpcomingCities.tsx - Tailwind-Klassen, keine inline Styles - Server Component (kein 'use client')

③ Output-Format vorgeben

Plan, Code, Test, PR-Beschreibung – nenne, was du am Ende sehen willst.

GUTLiefere: 1. Plan (3-5 Bullets, was du anfasst) 2. Code mit Datei-Pfaden 3. Vitest-Test für die Helper-Funktion 4. PR-Beschreibung (Was / Warum / Brand-Compliance)

④ Brand‑Compliance immer mit‑adressieren

Mache es zur Routine, am Ende „BRAND‑Check" zu verlangen.

GUTAm Ende: prüfe gegen BRAND.md §7 (Voice) und §2 (Tokens). Liste auf, welche Tokens du verwendet hast.

⑤ Iteriere klein

Lieber 5 Prompts à „mach Schritt 2" als 1 Prompt mit allem. Kleine Diffs = einfache Reviews = wenig Bugs.

03 Prompt‑Patterns für Strolly

Vier wiederkehrende Muster, die du immer wieder brauchst. Kopier‑Vorlagen.

🆕 Pattern A — Neue UI‑Komponente

Lies BRAND.md (§2 Tokens, §5 Komponenten, §7 Voice). Baue eine neue Komponente <TourCard> unter components/ui/TourCard.tsx. Props: - title: string - duration: number (Minuten) - stations: number - coverUrl: string Design: - Card-Style aus BRAND.md (border-radius lg, shadow-sm) - Cover oben (aspect 16/10) - Badge oben mit Bezirk-Name (Pill, teal-light/teal-dark) - Title in Poppins 700 22px - Meta-Row: Uhr-Icon + Pin-Icon (lucide) Liefere: Plan → Code → Storybook-Story.

🛠 Pattern B — Refactor

Refactor: Ersetze alle hardgecodeten Farben in /app/landing durch Tailwind-Tokens (siehe BRAND.md §2). Schritte: 1. Liste mir zuerst alle Vorkommen auf (grep, kein Code-Change). 2. Warte auf mein OK. 3. Dann den Refactor in einem Commit, mit Vorher/Nachher-Tabelle in der PR-Beschreibung.

🐞 Pattern C — Bug Fix

Bug: GPS-Trigger feuert mehrfach, wenn man sich an einem Hotspot für mehr als 30 Sekunden aufhält. 1. Reproduziere den Bug in einem failing Test (Vitest). 2. Erkläre die Ursache in 2-3 Sätzen. 3. Fix mit minimalem Diff. 4. Test grün. Datei: /lib/player/gps-trigger.ts

📝 Pattern D — Copy / Content

Schreibe 3 Varianten für die Hero-Headline der Berlin-Landing. Constraints (BRAND.md §7): - Du-Form - Max. 5 Wörter - Pointe oder Frage, keine Substantivkette - Lokal-bezogen (Berlin-Vibe ok, aber nicht klischeehaft) Liefere nur die 3 Varianten + 1 Satz, was die jeweilige Variante transportiert.

04 Konkrete Beispiel‑Prompts

Direkt einsetzbar. Kopieren, anpassen, los.

📦 „Landing‑Page von 0 aufsetzen"

Initialisiere die Landing-Page für Strolly München auf Next.js 15 (App Router). Schritt 1 — Plan: - Sektionen: Hero, Features, How-it-Works, Tours, Cities, CTA - Komponenten-Struktur unter /components/sections/* - Alle Tokens aus BRAND.md, Tailwind config angepasst Schritt 2 — Setup: - Tailwind config mit Tokens aus BRAND.md §2 - Google Fonts (Poppins, Inter) via next/font - /public/assets mit strolly-logo.svg + strolly-mark.svg Schritt 3 — Komponenten einzeln, ich gebe nach jeder OK. Starte mit Schritt 1.

🎨 „Komponente nach Design bauen"

Baue <PlayerToast> nach folgendem Verhalten: - Erscheint unten am Screen, wenn eine Story getriggert wird - Slide-up Animation 200ms - Cover-Icon links (rund, teal background), Title + Dauer mittig, Play-Button rechts - Auto-dismiss nach 6 Sek, es sei denn user hovert/touched Code in components/player/PlayerToast.tsx. Storybook-Story mit 3 States: idle, hover, audio-playing. Tokens: BRAND.md §2 — keine Hex-Codes hardcoden.

🧪 „Tests für vorhandene Logic"

Schreibe Vitest-Tests für /lib/player/distance.ts (Haversine-Berechnung). Test-Cases: - Distanz München → München (Identität) = 0 - Distanz Marienplatz → Olympiapark ≈ 4.2 km (±100m) - Negative Koordinaten korrekt - Edge Case: Antipoden ≈ 20015 km - Throws bei NaN-Input Coverage-Ziel: 100% für die Datei.

🚀 „PR vorbereiten"

Stage die aktuellen Änderungen als zwei Commits: 1. feat(landing): add upcoming cities section 2. test(landing): add vitest for cities helper Dann erstelle die PR-Beschreibung nach CLAUDE.md-Format (Was / Warum / Brand-Compliance / Screenshots). Branch-Name: feat/landing-upcoming-cities.

05 Daily Workflow

So sieht ein normaler Strolly-Arbeitstag mit Claude Code aus.

PhaseWas du tust
Morgens · Plan „Heute will ich X bauen. Lies BRAND.md und das relevante Verzeichnis. Schlage 3 Schritte vor."
Implementieren Schritt für Schritt. Nach jedem Schritt: kurzer Check, dann „weiter mit Schritt 2".
Selbst‑Review „Review deinen eigenen Diff gegen CLAUDE.md Checklist. Was würdest du als Reviewer kritisieren?"
Tests „Was fehlt an Tests? Schreibe das fehlende Stück."
PR „Erstelle PR mit Beschreibung im CLAUDE.md-Format."
Nach Review „Hier die Kommentare aus dem Review: [...]. Adressiere sie, halte die Diffs klein."

Mini-Prompts, die du täglich brauchst

  • „Plan zuerst, kein Code" – wenn du nur ein Konzept willst.
  • „Zeig mir den Diff" – bevor er writet.
  • „Brand‑Check" – am Ende jeder UI‑Aufgabe.
  • „Erkläre, warum" – wenn er etwas anders gemacht hat als gedacht.
  • „Minimaler Diff" – wenn du Refactors klein halten willst.

06 Was du vermeiden solltest

Häufige Anti‑Patterns und ihre Gegenmittel.

SCHLECHTMach die Landing schön.
BESSERÜberarbeite die Hero-Section: Headline auf 5 Wörter, Subline mit Mention von „GPS" und „Geschichten", CTA-Button vergrößern auf padding 16/26.
SCHLECHTBau mir eine bessere Karte.
BESSERErsetze die aktuelle Map durch Mapbox GL (kostenpflichtig ok), Style: dark/Navy mit Teal Accents, Pins als <StrollyPin />, Cluster ab Zoom 12. Komponente unter components/map/StoryMap.tsx.
SCHLECHTMach das schneller.
BESSERProfile zeigt: TourList rendert in 320ms. Ziel: <100ms bei 50 Touren. Verdacht: useEffect für Distanz-Berechnung läuft pro Item. Fix mit useMemo + Web Worker, falls nötig.
Faustregel: Wenn dein Prompt < 5 Wörter ist, denk nochmal nach. Wenn dein Prompt > 300 Wörter ist, splitte ihn.

07 Cheatsheet

Die Quintessenz auf einer Bildschirmseite.

Das 5-Säulen-Prompt

KONTEXT:   Lies [Dateien], beachte [Section in BRAND.md]
AUFGABE:   Was soll getan werden (1-2 Sätze)
CONSTRAINTS:
            - Verbote (keine neue Lib, keine 'use client', ...)
            - Stack (Next.js / Vitest / Tailwind)
            - Datei-Pfade
OUTPUT:    Plan → Code → Test → PR-Beschreibung
CHECK:     Brand-Compliance gegen BRAND.md §X bestätigen

Quick Reference

Plan zuerstStatt direkt Code: „Liefere zuerst nur einen Plan, kein Code."
Halt, frag„Bei jeder Unklarheit: stoppe, frag, dann weiter."
Lies X„Lies BRAND.md §2 + §5 und beachte sie strikt."
Klein iterieren„Splitte in 3 Commits, ich review nach jedem."
Brand-Check„Am Ende: prüfe gegen BRAND.md, liste benutzte Tokens auf."
Selbst-Review„Reviewe deinen Diff als wärst du ein strenger Senior."
Konkretisier„Was meinst du genau mit X? Schlag 3 Varianten vor."

Goldene Regeln in 7 Stichpunkten

  1. CLAUDE.md + BRAND.md im Repo-Root. Mehr Konfiguration braucht es nicht.
  2. Kontext vor Aufgabe. „Lies X, dann tue Y."
  3. Constraints explizit. Verbote sind so wichtig wie Anweisungen.
  4. Iteriere klein. 5 Mini-Prompts schlagen 1 Mega-Prompt.
  5. Plan vor Code bei allem > 30 Minuten Arbeit.
  6. Brand‑Check am Ende jeder UI‑Aufgabe.
  7. Wenn er rät, frag warum. Lieber einmal nachhaken als doppelt refactorn.
